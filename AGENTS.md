# Agent Guidelines & Project Instructions (`AGENTS.md`)

This repository is a high-performance, real-time **Augmented Reality Spatial Laser Harp & Audio-Visual Instrument** built with **TypeScript**, **Three.js WebGL**, **MediaPipe HandLandmarker**, and **Tone.js**.

Reference video: [`docs/4DD67AC2-B165-4EB3-AA5F-2C8DEF1971B9.mp4`](./docs/4DD67AC2-B165-4EB3-AA5F-2C8DEF1971B9.mp4).  
Master documentation: [`docs/documentation.md`](./docs/documentation.md).

When working in this repository, Antigravity and any contributing AI agent **MUST adhere strictly to the following architectural rules, conventions, and delivery protocols**.

---

## 🚨 Non-Negotiable Core Rules

### 1. Zero UI Framework Rule (Pure TypeScript & Vanilla DOM)
- **NEVER** introduce React, Vue, Svelte, Angular, Solid, or virtual DOM libraries.
- The UI must remain **100% vanilla TypeScript** with lightweight, direct DOM elements for HUD, controls, and diagnostics.
- Ensure the application maintains a deterministic **60 FPS** with minimal CPU overhead.

### 2. Strict Layer Decoupling & Modular Architecture
Keep code strictly divided into decoupled subsystems:
```
src/
├── vision/      # Camera capture & MediaPipe HandLandmarker abstraction
├── gestures/    # Gesture recognition (pinch detection, collision solving)
├── instruments/ # Spatial strings, wave physics, instrument contracts
├── audio/       # Web Audio / Tone.js synthesis, presets, scale mappers
├── render/      # Three.js scene, video background, shaders, particle pool
├── core/        # EventBus, RAF ticker loop, reactive AppState
└── ui/          # Lightweight HUD & preset controls
```
- **DO NOT** couple vision or rendering directly to audio. Use the `EventBus` or explicit controller coordinators in `src/main.ts`.

### 3. Local & Offline Asset First
- The application must function offline without CDN dependencies.
- Models and WebAssembly binaries are stored locally in:
  - `public/models/hand_landmarker.task`
  - `public/wasm/vision_wasm_internal.*`
- Never load core runtime vision tasks from external CDNs (unpkg, jsdelivr) during production.

### 4. Zero Garbage Collection Inside the Render/Tick Loop
- **NO per-frame allocations** inside `requestAnimationFrame` ticks:
  - Pre-allocate Three.js `Vector3`, `BufferGeometry`, `Float32Array`, and mesh pools during initialization.
  - Mutate existing attributes (`needsUpdate = true`) instead of constructing new objects every frame.
  - Prevent garbage collection pauses (jank/stutter) during hand movements and audio plucking.

### 5. Strict TypeScript Typing
- Maintain full type safety (`tsconfig.json` with strict mode enabled).
- Avoid `any` types; define and extend proper contracts in `src/types/`:
  - `vision.ts`: `HandPose`, `Point3D`, `Handedness`, joint connection indices.
  - `gestures.ts`: `PinchState`, `DualPinchState`, `HandGestureState`.
  - Future types: `InstrumentState`, `SoundPreset`, `PluckEvent`.

### 6. Documentation & Artifact Persistence Rule
- **Always Save Artifacts in `docs/`**: Every planning document, architecture specification, walkthrough, or visual analysis generated by Antigravity MUST be mirrored and persisted directly in the `docs/` directory (consolidated in [`docs/documentation.md`](./docs/documentation.md)).
- **Master Documentation as Single Source of Truth**: [`docs/documentation.md`](./docs/documentation.md) is the master repository for the system architecture diagrams, project directory scaffolds, and milestone roadmap progress. The root [`README.md`](./README.md) remains lightweight with quickstart commands and links.
- **Immediate Documentation Sync**: After ANY code changes are applied (new features, refactors, bug fixes, or advancing milestones), Antigravity **MUST immediately update** [`docs/documentation.md`](./docs/documentation.md) to reflect the exact state of the project.
- **Strict Code-Doc Consistency Verification**: Antigravity MUST actively verify that all file paths, class/interface signatures, directory trees, and milestone progress tables in `docs/` match the codebase with 100% fidelity. Never allow the documentation to drift out of sync with actual code.

## 🚦 Phased Delivery & Verification Protocol

Development proceeds strictly in progressive milestones from basic to advanced:

| Step | Milestone | Status | Key Deliverable |
| :---: | :--- | :---: | :--- |
| **Step 1** | **Core Foundation & Skeleton Tracking** | ✅ Completed | Mirrored camera feed, local MediaPipe WASM/model, 21-joint skeleton (red joints, green bones), HUD. |
| **Step 2** | **Pinch Detection & Dynamic Elastic String** | ✅ Completed | Hysteresis pinch detection, dual-hand elastic string, ruler/fret tick marks, animated anchor reticles. |
| **Step 3** | **Mid-Air Spatial String Anchoring** | ✅ Completed | Releasing pinch locks 3D strings with fret/ruler tick marks in space; build multi-string harp. |
| **Step 4** | **Real-Time Audio Synthesis & Plucking Engine** | ⏳ Next Up | Finger-string collision solver, velocity-sensitive plucking, Karplus-Strong string synthesis. |
| **Step 5** | **Visual Physics, Wave Oscillation & Sparks** | ⚪ Upcoming | Damped harmonic wave equations on plucked strings, GPU spark particle burst, UnrealBloom glow. |
| **Step 6** | **Modular Sound Presets & Instrument Settings** | ⚪ Upcoming | Runtime sound preset selector (Plucked Harp, Laser Synth, Ambient Chime) and musical scales. |

### Milestone Protocol:
1. Focus only on the active step. Do not jump ahead without user alignment.
2. Verify every code change by running `npm run build` to confirm zero TypeScript errors.
3. Keep the progress tables and implementation logs in `docs/documentation.md` updated when completing a step.
4. Verify complete consistency between the codebase (file structure, exported symbols) and documentation before concluding any turn.
